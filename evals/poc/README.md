# evals/poc/

Artifact PoC outputs (AES-P4.1–P4.5). Committed so a human can read them, and
regenerated by CI to prove they are reproducible.

| File | From | Issue |
|---|---|---|
| `cost-stack.svg` | `specs/cost-stack.chart.json` | SUE-453 |
| `cost-flow.mmd` | `specs/cost-flow.diagram.json` | SUE-453 |
| `brief.md` | article v3 + the plan's brief decision | SUE-452 |
| `deck.md` | article v3 + the plan's slides narrative | SUE-454 |
| [`FINDINGS.md`](FINDINGS.md) | what the artifacts showed, and their limits | SUE-453 |

```bash
npm run poc:build   # regenerate
npm run poc:check   # fail if anything would change
npm run test:poc    # determinism, refusals, lineage, staleness
```

**The spec is the artifact; the render is a build product.** That is why the
specs are committed beside the outputs, and why `poc:check` is a meaningful
test rather than a formality.

Everything here is deterministic. The brief and deck generators are compilers,
not writers — see the limits section of `FINDINGS.md`.
